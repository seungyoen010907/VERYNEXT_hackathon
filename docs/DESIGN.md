# DESIGN

> 화면을 만들 때 AI가 따르는 규칙. 프리셋 하나를 골라 맨 아래 "내 선택"에 적는다.

## 1. 원칙

- 랜딩페이지가 아니라 도구다. 입력하고 결과 보는 게 한 화면에서 끝난다.
- 주인공은 검증 리포트와 체크리스트다. 폼은 조용하게, 결과는 읽기 좋게.
- 장식 대신 여백과 위계로 정리한다: 서비스 이름 > 섹션 라벨 > 본문.
- 금액은 항상 `lib/format.ts`의 `won()`으로 표시한다 (예: 35,000,000원).

## 2. 기술 규칙

- 스타일은 Tailwind만 쓴다 (create-next-app에 이미 들어 있음). shadcn, MUI 같은 UI 라이브러리는 오늘 추가하지 않는다.
- 색은 `app/globals.css`의 CSS 변수로만 정의하고, 컴포넌트에는 hex 값을 직접 쓰지 않는다.
- 변수 이름: `--bg`, `--card`, `--text`, `--muted`, `--border`, `--accent`, `--warn`(확인 필요), `--caution`(주의)
- 폰트는 `next/font/google`의 `Noto_Sans_KR`를 쓴다. 기본 폰트 Geist는 한글 글꼴이 없다.

## 4. 레이아웃

- 본문 최대 너비 672px (`max-w-2xl`), 가운데 정렬, 좌우 패딩 16px. 거래방(`/deals/[id]`)만 화면 가로폭을 꽉 채운다.
- 거래방 화면 구성 (데스크톱은 화면 높이에 딱 맞추고, 페이지 전체가 아니라 영역 안에서만 스크롤한다):
  - 왼쪽 사이드바: 위아래로 화면 끝까지 붙는다. 체크리스트와 제출된 자료가 들어 있고, 내용이 길면 사이드바 안에서 스크롤한다.
  - 오른쪽 패널(하나로 합친 흰 카드): 맨 위에 제목(점포 주소) + "검증 리포트 보기" + 매물 정보 한 줄 + 가로 로드맵이 고정된다. 가운데 메시지 목록만 스크롤된다. 메시지 입력칸은 맨 아래에 고정된다.
  - 로드맵 가로 길이는 메시지 영역과 같다 (둘 다 오른쪽 패널 안).
- 거래방 안에서는 테두리선(stroke)을 쓰지 않는다. 영역 구분은 배경색(`--bg` 회색 바탕 위 `--card` 흰 카드)과 여백으로만 한다.
- 사이드바는 기본으로 열려 있고, 햄버거 아이콘(줄 세 개)을 누르면 접히고 다시 누르면 펼쳐진다. 접히면 오른쪽 패널이 넓어진다.
- 모바일(768px 미만)에서는 사이드바가 오른쪽 패널 위에 쌓이고, 메시지 입력칸은 화면 아래에 붙어 따라온다.
- 모바일 폭(375px)에서도 가로 스크롤이 생기면 안 된다. 월별 매출표처럼 넓은 표만 표 영역 안에서 가로 스크롤을 허용한다.
- 헤더: 왼쪽에 서비스 이름 + 한 줄 설명, 오른쪽에 "내 거래방 목록" 링크와 `RoleSwitch`(양도인으로 보기 / 양수인으로 보기).
- 현재 역할은 헤더에 항상 보이게 한다 (지금 누구 화면인지 헷갈리지 않게).

## 5. 컴포넌트

### 거래방 만들기 폼 (`app/deals/new/page.tsx`)
- 입력칸은 전체 너비, placeholder에 예시를 넣는다. (예: 주소 "서울 마포구 ○○로 12, 1층", 권리금 "60000000")
- 업종은 select: 음식점 / 카페 / 기타
- 금액 입력칸 아래에 `won()`으로 읽기 쉬운 금액을 작게(`--muted`) 보여준다.
- 양도인 주장 월 순수익은 "(선택)"으로 표시한다.

### 주 버튼
- 전체 너비, `--accent` 배경.
- 로딩 중에는 비활성화하고 문구를 바꾼다: 거래방 만들기 → "만드는 중...", 검증 → "검증 중... (30초~1분)", 업로드 → "올리는 중..."

### 계약 로드맵 (`components/Roadmap.tsx`)
- 단계를 가로로 한 줄에 보여준다 (번호 동그라미 + 아래 단계 이름, 사이를 선으로 잇기). 폭이 좁으면 로드맵 안에서만 가로 스크롤. `done`은 체크 표시와 `--muted`, `current`는 `--accent` 굵게, `todo`는 `--muted`.

### 체크리스트 (`components/Checklist.tsx`)
- 현재 역할의 항목만 보여준다. 상대 역할 항목은 접힌 "상대방 진행 상황"에서 개수와 상태만 보여준다.
- 할 일은 순서대로 번호를 붙이고, 처음 3개만 보여주고 "N개 더 보기"로 펼친다.
- 할 일에는 태그로 차이를 보여준다: "지금 단계"(`--accent` 채운 태그, 카드도 옅은 파란 배경), "다음 단계"(회색 태그, 흐리게), "파일 제출"(자료를 올려야 하는 항목).
- 끝낸 항목은 덜 중요하게(작은 글씨, `--muted`, 체크 표시) 맨 아래에 카드 여러 장이 뒤로 겹쳐 쌓인 모양("완료 N개")으로 접어 두고, 누르면 펼친다.
- 제출된 자료도 처음 3개만 보여주고 "N개 더 보기"로 펼친다.
- 항목: 제목, 상태 배지(할 일 / 제출 완료 / 확인 완료), "어디서 떼나요?" 버튼(누르면 `guide` 펼침).
- 자료 항목은 양도인으로 볼 때 업로드 버튼이 있다.

### 메시지 (`components/Messages.tsx`)
- 오른쪽 패널의 가운데. "메시지" 같은 제목은 달지 않는다. 메시지 목록만 스크롤하고, 새 메시지가 오면 맨 아래로 내려간다. 입력칸은 맨 아래에 고정한다.
- 내 메시지는 오른쪽, 상대 메시지는 왼쪽, 에이전트(`agent`) 메시지는 가운데 `--muted` 배경 카드.
- 각 메시지 위에 역할 이름(양도인 / 양수인 / 에이전트)과 시각을 작게 표시한다.

### 검증 리포트 (`components/ReportView.tsx`)
- 섹션 순서: 요약 카드(신뢰도 등급 + `headline`) → 핵심 위험 Top 3 (Step 5) → 확인 필요 항목 → 주장 vs 실제 → 월별 매출표 → 협상 포인트 (양수인만) → 양도인에게 요청할 것
- 신뢰도 등급은 크게(A~D). 확인 필요는 `--warn` 배지, 주의는 `--caution` 배지.
- 월별 매출표는 숫자 오른쪽 정렬, 고정폭 숫자(`tabular-nums`). '확인 필요'인 칸은 `--warn` 글자색.
- 맨 아래에 작게: "이 리포트는 제출된 자료를 기준으로 한 참고 자료이며, 법률·세무 판단은 전문가 확인이 필요해요."

### 거래방 목록 아이템 (`app/deals/page.tsx`)
- 카드 전체가 링크다.
- 윗줄: 업종 · 생성 날짜 (작게, `--muted`)
- 점포 주소 (굵게), 아랫줄: 현재 단계 이름 + "내 할 일 N개"

## 9. 확장 화면 규칙 (PRD 9번 화면 1~8)

- (2026-11-01 개정) 10번이 9번보다 우선한다. 기존 화면도 10번 기준으로 다시 정리한다. 새 화면도 같은 색 토큰(프리셋 A)과 폰트를 쓴다. 포인트 컬러는 `--accent` 하나.
- 새 화면은 B2B 데이터 관리 도구처럼: 표와 목록 중심, 카드 남발 금지, 그림자·그라데이션·네온·장식용 AI 캐릭터 금지. 모서리는 기존과 같은 값(12px)을 넘기지 않는다.
- 데스크톱 우선, 모바일에서도 가로 스크롤 없이(넓은 표만 표 안에서 스크롤).
- 상태 표시는 태그(배지)로 통일한다.
  - 공개 등급: L0 공개 / L1 NDA 후 / L2 승인 후 / L3 비공개
  - 신뢰 수준: 점주 진술 / 자료 제출 / 교차 확인 / 외부 검증 / AI 추정
  - 질문 상태: 질문 생성 / 전달 대기 / 응답 중 / 승인 대기 / 추가 자료 요청 / 답변 완료 / 거절 / 오류
- 값이 없으면 "미확인"(회색 태그). 0으로 쓰지 않는다.
- 숫자 옆에는 "근거" 버튼: 누르면 출처 자료, 기간, 신뢰 수준, 계산 가정을 펼친다.
- 샘플 데이터에는 항상 "샘플" 태그. 데모 사용자 전환에는 "데모 사용자" 표시.
- NDA는 "테스트 동의(법적 효력 없음)"라고 쓴다. "서명 완료", "본인인증 완료"라고 쓰지 않는다.
- AI 실사 센터(화면 7)는 3단: 왼쪽·가운데에 매물별 질문 상태 표, 오른쪽에 통합 분석. 채팅 말풍선으로 보여주지 않는다.

## 10. 화면 설계 개정 (2026-11-01, PRD 4.3·4.4·9번)

### 10.1 원칙

1. **역할마다 메뉴가 다르다.** 지금 역할에 필요 없는 메뉴는 보이지 않는다. 헤더 오른쪽 데모 사용자 전환은 그대로 둔다.
2. **한 화면에 주인공 하나.** 화면 맨 위에는 그 화면의 결론을 그래픽 하나로 보여주고(게이지·막대·연결도), 표와 근거는 그 아래에서 펼쳐 본다 (점진적 공개).
3. **여정이 보인다.** 홈 맨 위에 여정 바(양도인 6단계 / 양수인 5단계, PRD 4.4)를 두고, 지금 단계와 "다음 할 일" 버튼 하나를 강조한다. 단계 상태는 실제 데이터로 계산한다.
4. **에이전트는 화면의 주체로 보이되 꾸미지 않는다.** 4종 에이전트(PRD 4.3)는 기하학 아이콘 + 이름 + 실제 활동(숫자·최근 시각)으로 보여준다. 캐릭터·말풍선 연출 금지.
5. **숫자는 그림으로 먼저, 근거는 한 번에 하나.** 금액은 여전히 `won()`. 그래프 옆에 핵심 숫자 하나만 크게, 나머지는 작게.

### 10.2 IA (메뉴)

| 역할 | 메뉴 |
|---|---|
| 양수인 | 홈 · 매물 찾기 · AI 실사 · 비교 · 거래방 |
| 양도인 | 홈 · 내 매물 · 요청함 · 거래방 |

- 인수 조건은 양수인 홈의 "내 조건" 카드에서 연다 (메뉴에 두지 않음). 매물 등록은 양도인 "내 매물" 화면의 주 버튼.
- `/dashboard` → `/`로 보낸다. 데이터룸 탭은 4개(개요·자료·비용·시설·공개 범위), 양수인에게는 개요·자료만.

### 10.3 시각 언어

- 그래프는 SVG로 직접 그린다 (차트 패키지 추가 금지, docs/API.md 7번). 공용 컴포넌트는 `components/viz/`.
- 색: 주 계열 `--accent`, 보조 계열 `--accent` 40%·`--muted`, 문제 `--warn`, 주의 `--caution`. 새 색 변수는 만들지 않는다.
- 쓰는 그래프:
  | 그래프 | 어디 | 보여주는 것 |
  |---|---|---|
  | 반원 게이지 | 매출 증빙률, 추천 점수 | 0~100%, 기준선(70%·90%) |
  | 월별 막대 | 매출 증빙 | 카드+배달 막대 + POS 점, 어긋난 달은 `--warn` |
  | 폭포 막대 | 양수인 기준 이익 | 매출 → −변동비 → 매출총이익 → −고정비 → 월순수익 |
  | 손익분기 막대 | 손익분기점 | 현재 매출 막대 위 손익분기점 눈금, 여유/부족 |
  | 회수 타임라인 | 권리금 회수 | 바닥권리금 제외·포함 두 줄 + 목표 개월 세로선 |
  | 범위 막대 | 시설권리금 | AI 추정 범위(띠) + 양도인 반영가(점) |
  | 비교 막대 | 비교 | 지표마다 매물 3개 가로 막대, 가장 나은 값 강조 |
  | 연결도 | AI 실사 | 양수인 AI(가운데) ↔ 양도인 AI 3개, 선 색 = 질문 상태 |
  | 여정 바 | 홈 | 단계 점 + 진행 선 |
- 그래프마다 `aria-label`로 핵심 숫자를 글로 적는다. 색만으로 구분하지 않는다 (태그·글자 같이).

### 10.4 모션

- `app/globals.css`의 키프레임만 쓴다: `viz-grow`(막대가 0에서 차오름), `viz-fade`(아래에서 살짝 떠오름), `viz-flow`(연결선 점선이 흐름), `viz-pulse`(점이 깜빡임).
- 처음 나타날 때 한 번만 400~700ms ease-out. 계속 반복하는 모션은 **실제로 기다리는 중인 상태**(질문 전달 대기·응답 중)에만 쓴다.
- 조정값을 바꾸면 막대 길이가 300ms로 바뀐다 (transition).
- `prefers-reduced-motion: reduce`면 모션을 모두 끈다.

## 11. UX 라이팅 (2026-11-01)

### 11.1 원칙

1. **해요체, 한 문장에 한 가지.** 설명은 40자 안팎. 길어지면 문장을 나누거나 "자세히"로 접는다.
2. **버튼은 동사로 끝낸다.** "자료 올리기", "승인", "AI 실사 시작". "확인", "OK"처럼 무엇이 일어나는지 모르는 말은 쓰지 않는다.
3. **설명은 "하면 → 된다".** 예: "NDA에 동의하면 매출 요약을 볼 수 있어요."
4. **빈 화면은 이유 + 다음 행동.** 예: "아직 매물이 없어요. 첫 매물을 등록해 보세요." + 버튼.
5. **에러는 무엇이 안 됐는지 + 어떻게 하면 되는지.** 사용자를 탓하지 않는다.
6. **내부 용어를 화면에 드러내지 않는다.** L0~L3 코드, 영어 에이전트 이름, "코드 계산", 테이블 이름 대신 아래 용어를 쓴다.
7. **숫자가 주인공이면 숫자를 앞에.** "처리할 요청 3건"보다 큰 "3" + 작은 "처리할 요청".
8. "데모" 같은 시연용 표시는 화면에 쓰지 않는다. 단 샘플 매물의 "샘플" 태그와 NDA의 "법적 효력 없음"은 사실을 알리는 말이라 남긴다.
