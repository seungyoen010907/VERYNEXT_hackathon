## 0. MVP 핵심 — AI 에이전트 기반 점포 병렬 실사 및 비교 (2026-11-01 개정)

양수인이 인수 조건을 입력하면, 양수인 AI 에이전트가 여러 점포의 양도인 AI 에이전트와 정보를 교환하고, 접근 권한에 따라 매물 실사 비교표를 자동으로 완성한다.

- 양도인은 매물 정보와 증빙자료를 등록하고 정보별 공개 조건을 정한다.
- 양수인은 예산·희망 지역 등을 입력하고 AI 실사 센터에서 "추천 매물로 AI 실사 시작"을 누르면, AI가 맞는 매물을 고르고 매물마다 필요한 정보를 요청하며 확보한 데이터를 비교표에 자동 반영한다.
- 비공개 정보는 NDA 체결이나 양도인 승인 등 미리 정한 조건이 채워지면 AI가 추가로 조회·분석한다.
- **핵심 경험:** 양수인은 매물마다 연락하거나 따로 실사를 요청하지 않고, 하나의 화면에서 여러 점포의 정보를 계속 확인한다.
- **에이전트 대화를 보여준다:** AI 실사는 결과만 보여주지 않는다. 양수인 AI와 매물별 양도인 AI가 **실제로 주고받는 질문·답을 매물별 대화창으로 실시간 표시**한다. 화면의 말풍선은 모두 DB에 저장된 실제 질문·답이며, 대본·가짜 진행 효과는 쓰지 않는다.

**전체 흐름**

- 양도인: 매물 등록 → 자료 업로드 → AI 데이터 구조화 → 공개 권한 설정 → 매물별 AI 에이전트 생성
- 양수인: 인수 조건 입력 → (AI 실사 센터에서 시작 버튼) → AI 에이전트 생성 → 매물 자동 추천 → 매물별 AI에 병렬 질의(대화창 실시간 표시) → 비교표 생성 → NDA·승인 조건 충족 → 심층 실사 → 비교표 자동 갱신

| 우선순위 | 기능 | 설명 | 완료 기준 |
|---|---|---|---|
| P0 | 양도인 매물 등록 | 주소, 업종, 상호명, 브랜드 유형, 면적, 층수, 보증금, 월세, 권리금, 권리금 구성·산정 근거, 주차, 매물 테마 등을 웹 폼으로 등록 | 매물을 만들고 고칠 수 있고, 매물별 정보가 DB에 저장된다 |
| P0 | 자료 업로드·AI 구조화 | 매출·비용·임대차·시설 자료(PDF, 엑셀, 이미지)를 올리면 AI가 기간별 매출, 비용, 운영 조건 등을 구조화. 빠진 정보는 양도인에게 알린다 | 주요 항목이 자동 추출되어 원본 출처와 연결 저장되고, 양도인이 추출값을 확인·수정할 수 있다 |
| P0 | 매물별 AI 에이전트 | 매물마다 AI 에이전트가 매물 DB와 증빙자료로 질문에 답하고, 정보가 부족하면 추가 자료를 요청 | 매물마다 데이터 범위가 분리되고, 그 매물 데이터만으로 구조화된 답을 만든다 |
| P0 | 공개 권한 설정 | 정보별 공개 조건: 일반 공개(L0), NDA 후(L1), NDA + 양도인 승인 후(L2), 비공개(L3) | 공개 등급을 지정·변경할 수 있고, 서버가 양수인 권한에 따라 조회를 제한한다 |
| P0 | 양수인 인수 조건 입력 | 총예산, 희망 지역, 선호 업종, 목표 월수익, 근무 가능 시간 등을 웹 폼으로 입력 | 조건이 양수인 프로필에 저장되고 추천·실사에 쓰인다 |
| P0 | 양수인 AI 생성·매물 추천 | 양수인이 AI 실사 센터에서 "추천 매물로 AI 실사 시작"을 누르면, 양수인 AI가 예산·지역·업종 우선으로 맞는 매물(최대 3개)을 고르고 실사를 시작. 조건 저장만으로 자동 시작하지 않는다 | 양수인이 매물을 따로 고르지 않아도 후보가 정해진다. 맞는 매물이 부족하면 실제로 찾은 것만 쓴다 (직접 바꿔 고르기는 보조 기능) |
| P0 | 에이전트 간 병렬 정보 교환 | 양수인 AI가 매물 3개의 AI에 매출, 비용, 임대차, 운영 조건 등을 동시에 질의. 각 매물 AI는 허용된 자료로 답하고, 부족하면 추가 요청 | 병렬로 처리되고 답·미확인·추가 요청이 매물별로 저장된다. **질문 → 답하는 중 → 답이 대화창에 실시간으로 붙는다** |
| P0 | 실시간 비교표 | 권리금, 월매출, 월순수익, 운영·임대차 조건 등을 같은 항목으로 정리하고 진행에 따라 갱신 | 실사를 시작하면 자동 생성되고, 새 데이터가 오면 해당 칸이 갱신(표시)된다. 출처·검증 상태를 볼 수 있다 |
| P0 | 비공개 정보 접근·자동 심층 실사 | 비공개 칸에 열람 조건 표시. NDA·양도인 승인이 채워지면 AI가 추가 분석 (MVP는 테스트용 NDA 동의) | 승인 전에는 노출되지 않고, 조건 충족 뒤 **별도 질문 없이** 해당 답과 칸이 자동 갱신된다 |
| P0 | 양수인 직접 질문 | 대화창에서 양수인이 매물마다 궁금한 점을 직접 묻는다. 내 AI가 먼저 질문에 필요한 자료 범위(매출·비용·운영·임대차·시설·공개 기본정보)를 확인해 대화창에 밝히고, 양도인 AI가 그 범위에서 공개 권한이 있는 자료로만 근거와 함께 답한다 | 권한 없는 값은 답에 나오지 않는다(NDA·승인 안내로 바뀜). 자료로 답할 수 없는 부분(양도 이유·협상 등)은 추측하지 않고 "양도인에게 전달"이라고 밝히며, 양도인이 직접 답하면 "점주 진술"로 붙는다 |
| P0 | AI 추가 정보 요청·응답 | 양수인 AI가 빠진 정보를 양도인에게 질문. 양도인은 글로 직접 답하거나 자료를 추가 업로드 | 자료를 올리면 멈춘 질문에 AI가 자동으로 다시 답하고 비교표에 반영된다. 글 답변은 "점주 진술"로 대화창에 표시된다 |

## 1. 제품 개요

### 1.1 한 줄 요약

**양도인의 민감한 영업정보는 보호하면서, 양수인의 AI 에이전트가 여러 양도인의 AI 에이전트와 정보를 주고받아 여러 점포의 실제 수익성과 인수 적합성을 비교하는 플랫폼.**

이번 MVP의 핵심은 **AI 에이전트 간 통신(F07)**이다. AI가 채팅 답변만 만드는 것이 아니라, 실제로 다른 매물의 AI에 질문을 보내고 응답을 받아 분석한다.

### 1.2 제품 비전

점포를 사고파는 모든 사람이 자신만의 AI 에이전트를 갖는다.

- **양도인 에이전트**는 매장의 매출·비용·운영·계약 정보를 모으고 관리하며, 양도인이 허용한 범위 안에서 잠재 양수인의 질문에 답한다.
- **양수인 에이전트**는 양수인의 예산, 희망 수익, 선호 업종, 운영 경험을 이해하고, 이를 바탕으로 여러 매장의 에이전트와 정보를 주고받으며 맞는 매물을 찾고, 비교하고, 검증한다.

결국 양도인과 양수인이 직접 하던 정보 수집, 반복 질문, 초기 실사를 AI가 대신한다.

### 1.3 핵심 가치

- **양도인:** "내 가게의 민감한 정보를 보호하면서, 더 많은 구매자에게 효율적으로 설명할 수 있다."
- **양수인:** "일일이 연락하고 서류를 확인하지 않아도, 여러 가게가 나에게 맞는지 비교할 수 있다."

## 2. 문제

### 2.1 고객 문제

점포 양도양수 시장에는 거래에 필요한 정보가 존재하지만, 이를 자유롭게 공개하거나 활용하기 어렵다.

**양도인의 문제**

- 가게를 판다는 사실이 직원, 손님, 건물주에게 알려지는 것을 꺼린다.
- 매출·비용·계약 정보가 POS, 배달앱, 세무 자료, 종이 문서에 흩어져 있다.
- 잠재 양수인마다 같은 자료를 요청받고 같은 질문에 반복해서 답해야 한다.
- 살 의사가 불확실한 사람에게 어디까지 공개해야 할지 판단하기 어렵다.

**양수인의 문제**

- 인수 전에 실제 매출, 순수익, 운영 부담, 권리금 적정성을 확인해야 한다.
- 상세 정보는 양도인의 승인을 받거나 직접 문의해야 볼 수 있다.
- 매물마다 제공되는 자료의 종류와 기준이 달라 비교하기 어렵다.
- 여러 매물을 깊이 검토하려면 시간과 노력이 많이 든다.
- 양도인이 말한 매출이 부풀려져 있어도 확인할 방법이 마땅치 않다.

### 2.2 핵심 문제 가설

**거래 초기의 정보 공개 제약과 표준화되지 않은 데이터 때문에, 양수인의 매물 탐색·검증 비용과 양도인의 반복적인 정보 제공 비용이 높다.**

AI가 자료 수집·표준화, 권한 기반 질의응답, 여러 매물 비교를 자동화하면 이 비용을 줄일 수 있다.

## 3. 타깃 고객

### 페르소나 A — 양수인 (1차 타깃)

**상황:** 기존 음식점을 인수해 창업하려는 예비 소상공인. 나이·성별보다 첫 창업 여부, 인수 경험, 투자 가능 금액으로 나눈다.

**목표**

- 안정적인 월수익 확보
- 투자금 손실 위험 최소화
- 내 예산과 운영 능력에 맞는 점포 인수

**핵심 질문**

- "실제로 한 달에 얼마를 버는 가게인가?"
- "내가 운영해도 이만큼 벌 수 있는가?"
- "권리금은 적정한가?"
- "다른 가게와 비교하면 어떤가?"

### 페르소나 B — 양도인

**상황:** 지금 운영 중인 음식점을 넘기려는 점주. 동업자가 있으면 동업자의 동의도 필요하다.

**목표**

- 가게의 영업 가치를 최대한 인정받기
- 빠르고 안전한 거래 성사
- 직원·손님·영업정보 보호
- 반복적인 구매자 응대 최소화

**핵심 질문**

- "내 가게를 얼마에 팔 수 있을까?"
- "정말 살 의향이 있는 사람은 누구인가?"
- "어디까지 정보를 공개해야 할까?"
- "자료 준비가 얼마나 번거로울까?"

### 초기 집중 시장

카드·배달 매출 비중이 높은 수도권 음식점·카페. 매출 자료가 디지털로 남아 있어 검증하기 쉽다.

## 4. 핵심 사용자 흐름

### 4.1 양도인 — AI 매물 등록

**Step 1. 매물 등록과 데이터룸 생성**

양도인은 웹 폼으로 기본 정보를 입력하고 자료를 올린다. AI는 올린 자료에서 정보를 뽑아 폼을 채우고, 빠지거나 불명확한 항목만 채팅으로 되묻는다.

기본 정보:

| 항목 | 내용 |
|---|---|
| 위치 | 주소(지번·도로명), 건물명 |
| 업종 | 외식업, 서비스업, 도·소매업, 예술·스포츠·시설업, 교육·학원업, 숙박업, 기타 |
| 금액 | 보증금, 월세, 희망 권리금 |
| 권리금 구성 | 영업권리금, 시설권리금, 바닥권리금과 각각의 산정 근거 |
| 브랜드 | 프랜차이즈 / 개인 매장, 상호명 |
| 층수 | 해당 층 / 전체 층 |
| 면적 | 평수 |
| 매물 테마 | 무권리, 급매, 프랜차이즈, 사무실, 공식 매물, 임대인 매물 등 (여러 개 선택 가능) |
| 주차 | 건물 전체 주차 대수, 점포가 쓸 수 있는 대수 |

올릴 수 있는 자료 (모두 선택, 나중에 추가 가능):

- 매출 자료: POS, 카드매출, 배달앱 정산 내역, 부가세 신고서
- 비용 자료: 재료비, 인건비, 공과금, 기타 운영비
- 계약 자료: 임대차계약서, 프랜차이즈 계약서
- 시설 자료: 매장·설비 사진, 시설 목록
- 기타 증빙 자료

**결과:** 매물 등록과 동시에 그 점포의 AI 에이전트와 데이터룸이 생긴다. 모든 정보는 원본 출처와 신뢰 수준(7.2)을 함께 저장한다.

**Step 2. 공개 범위 설정**

양도인은 정보와 자료마다 공개 등급(6번 L0~L3)을 정한다. 원본 자료뿐 아니라 AI가 만든 분석 결과도 따로 정할 수 있다. 양수인이 조건을 채우면 허용된 정보가 자동으로 열리고, 개별 승인이 필요한 자료는 양도인에게 요청이 간다.

**Step 3. 매물 공개와 AI 응대**

매물이 공개되면 양도인 에이전트가 양수인(또는 양수인 에이전트)의 질문에 답한다.

- 권한 안에서 매물 정보 제공
- 매출·비용·운영 조건 질문에 답변
- 추가 자료와 빠진 정보 확인
- 비공개 정보를 요청하면 열람 조건 안내
- 개별 승인이 필요한 요청은 양도인에게 전달

AI는 허용된 정보만 쓴다. 새 원본 자료를 공개할지는 양도인의 권한 설정을 따른다.

**Step 4. 구매자와 공개 현황 관리**

양도인은 대시보드에서 다음을 본다.

- 관심 양수인 목록과 공개된 구매 조건
- NDA 체결 여부
- 자료 열람 요청과 승인 상태
- AI 질의응답 주요 내역
- 추가 자료 요청
- 정보별 접근 권한 수정·회수

### 4.2 양수인 — 에이전트 기반 인수 검토

**Step 1. 인수 조건 입력**

양수인은 웹 폼으로 인수 조건을 입력한다. (채팅 온보딩은 쓰지 않는다.)

- 투자 가능 총예산 (권리금 + 보증금 + 예상 추가 투자비 기준)
- 희망 지역, 선호 업종
- 목표 월 순수익
- 직접 근무 가능 시간
- 관련 업종 운영 경험
- 희망 투자금 회수 기간
- 꼭 확인하고 싶은 문서

**Step 2. 에이전트 생성과 매물 추천**

조건을 저장한 뒤 AI 실사 센터에서 "추천 매물로 AI 실사 시작"을 누르면 양수인 에이전트가 생기고, 예산·지역·업종에 맞는 매물을 최대 3개 **자동으로 골라 실사를 시작**한다. 추천 매물마다 공개 정보를 모으고, 부족한 정보는 질문을 만들고, 권한이 필요한 정보는 따로 표시한다. 양수인은 매물 화면에서 대상을 직접 바꿔 고를 수도 있다.

**Step 3. 매물 비교표**

추천과 동시에 비교표가 만들어지고, 확보한 데이터가 들어오는 대로 채워진다. (비교 항목은 F05)

- 공개 정보는 바로 표시한다.
- 부족한 정보는 AI가 질문을 만든다. 요청할 수 있는 항목에는 "요청하기" 버튼을 둔다.
- 비공개 항목은 열람 조건을 표시한다.
- 새 정보가 들어오면 해당 칸을 갱신한다.
- 모든 값에 출처와 신뢰 수준을 표시한다.
- 정보가 없거나 확인되지 않은 칸은 빈칸이 아니라 "미확인"으로 표시한다.

**Step 4. 실사 채팅과 분석 리포트**

관심 매물을 고르면 그 매물의 실사 공간(거래방)에 들어간다. 양도인·양수인·에이전트가 같은 대화방에서 질의응답하고, 검증 리포트에서 매출 교차 검증 결과, 확인 필요 항목, 핵심 위험을 본다.

## 5. 핵심 기능

### F01. 양도인 AI 등록 (P0)

양도인이 긴 양식을 한 번에 다 채우지 않아도, 자료를 올리면 매물 정보가 채워진다.

- PDF, 엑셀, CSV, 이미지에서 정보 추출
- 추출값 확인·수정
- 빠진 항목 탐지 후 질문
- 자료별 출처 저장
- 자료가 부족해도 임시 저장하고 나중에 이어서 등록

완료 기준:
- 모든 정보를 한 번에 입력하지 않아도 된다.
- 원본 자료와 AI 추출값이 연결되어 있다.
- AI가 모르는 값을 지어내지 않는다.

### F02. 데이터룸 (P0)

매물별 비공개 자료 관리 공간.

- 자료 업로드와 종류 자동 분류 (매출·비용·시설·임대차)
- 자료별 공개 등급 설정
- 열람 요청 승인·거절
- 접근 기록 확인
- 권한 회수, 비공개 전환

완료 기준:
- 허가받지 않은 양수인은 원본 자료와 비공개 분석 결과를 볼 수 없다.
- 양도인은 양수인별 열람 상태를 확인할 수 있다.

### F03. NDA와 열람 승인 (P0)

민감한 정보를 보기 전에 양수인 본인확인과 전자 NDA(비밀유지계약)를 거친다.

- 양수인 본인확인
- NDA 전자서명, 서명 여부와 문서 버전 기록
- 양도인의 접근 승인
- 양수인별 자료 열람 권한 부여

접근 규칙은 6번 표를 따른다. NDA 체결만으로 모든 자료가 열리지 않는다.

### F04. 양수인 AI 에이전트 (P0)

양수인의 조건을 기준으로 매물이 맞는지 분석한다.

- 양수인 조건 저장
- 매물 관련 자연어 질의응답
- 양수인 조건 기준 수익성 계산
- 미확인 정보·위험 요인 탐지
- 양도인에게 추가 정보 요청
- 모든 분석에 출처와 가정 표시

예시: "이 매장의 월 순수익은 500만 원으로 제시되어 있지만, 현재 점주가 주 70시간 일하고 있어요. 직접 근무 가능 시간이 주 40시간이라면 추가 인건비를 빼고 봐야 해요."

### F05. 여러 매물 비교 (P0)

여러 매물을 같은 기준으로 비교한다. MVP는 3개, 이후 8~10개 이상으로 늘린다.

| 항목 | 내용 |
|---|---|
| 초기 투자금 | 권리금, 보증금, 추가 설비비 |
| 매출 | 최근 월별 실적, 평균, 변동성 |
| 실질 수익 | 확인된 비용과 추가 운영비를 반영한 추정 |
| 권리금 | 희망 가격, 투자금 회수 시나리오 |
| 운영 적합성 | 양수인의 근무시간·경험·인력 계획과의 차이 |
| 계약 위험 | 임대차·인수인계 관련 미확인 조건 |
| 검증 상태 | 확인된 자료, 빠진 자료, 신뢰 수준 |

완료 기준:
- 자료가 부족한 칸은 "미확인"으로 표시하고, 요청할 수 있으면 "요청하기" 버튼을 둔다.
- 기준이 다른 매출(예: 카드 승인액과 정산액)을 억지로 합치지 않는다.
- 모든 숫자에 출처와 계산 가정을 붙인다.
- 순위를 매기면 어떤 기준으로 매겼는지 표시한다.

### F06. 매출 교차 검증 리포트 (P0)

양도인이 제시한 매출이 자료끼리 맞는지 코드로 비교한다. (자세한 규칙은 `docs/API.md` 6번)

- 카드·배달·POS·부가세 자료의 같은 달 숫자 비교, 10% 넘게 차이 나면 "확인 필요"
- 양도인 주장 월매출과 검증된 월평균 비교
- 신뢰도 등급(A~D), 확인 필요 항목, 양도인에게 요청할 자료

### F07. 에이전트 간 통신 (P0, MVP 핵심)

양수인 AI가 여러 양도인 AI와 실제로 질문과 답변을 주고받는다. 모든 질문·답변은 DB에 저장되고 새로고침해도 남는다.

**질문 만들기 (양수인 AI)**
- 양수인 조건과 매물별 기존 자료를 보고, 매물마다 **빠진 정보에 대한 질문만** 만든다. 같은 질문을 모든 매물에 보내지 않는다.
- 질문 종류: 매출 / 비용 / 순수익 / 운영 조건 / 임대차 조건 / 시설·인수인계 / 자료 추가 요청
- 같은 양수인·매물·질문 종류·주제로 이미 보낸 질문은 다시 보내지 않는다 (서버에서 중복 검사).

**답하기 (양도인 AI)** — 순서대로:
1. 질문을 받는다.
2. 답하려면 어떤 정보가 필요한지 정한다.
3. **그 매물의 데이터룸만** 검색한다. 다른 매물 자료는 검색 대상이 아니다.
4. 정보별 공개 권한을 **서버 코드로** 확인한다.
5. 허용된 정보만 근거(자료 이름, 기간, 신뢰 수준)와 함께 답한다.
6. 승인되지 않은 정보는 답하지 않고 양도인 승인 요청으로 바꾼다.
7. 관련 자료가 없으면 "자료 없음"으로 답한다.

답변 종류: 자동 응답 / 양도인 승인 필요 / 추가 자료 필요 / 자료 없음 / 접근 거부.
AI는 권한이 없는 자료 내용을 추측하거나 돌려 말하지 않는다. 권한 없는 자료는 AI에게 아예 넘기지 않는다.

**질문 상태:** 질문 생성 → 전달 대기 → 양도인 AI 응답 중 → (양도인 승인 대기 / 추가 자료 요청) → 답변 완료 / 거절 / 오류

**양도인 승인:** 양도인 대시보드의 구매자 요청 관리에서 요청한 구매자, 질문, 요청 자료, 요청 이유, 공개 등급, NDA 상태를 보고 승인·거절한다. 승인한 자료만 양수인 AI가 쓸 수 있다.

**자동 재처리:** 양수인이 NDA에 동의하면 "NDA가 필요하다"며 멈춘 질문을, 양도인이 승인하면 승인 대기 질문을, 양도인이 자료를 추가하면 "추가 자료 필요" 질문을 AI가 별도 요청 없이 다시 처리한다.

**양수인 직접 질문:** 대화창 입력칸에서 양수인이 직접 묻는다. 순서: (1) 질문 저장·표시 (2) 내 AI가 필요한 자료 범위를 고른다 (AI + 키워드, AI가 실패해도 키워드로) (3) 양도인 AI가 그 범위의 허용된 값만으로 답한다 (4) 자료로 답할 수 없는 부분은 양도인에게 넘기고 그 사실을 답에 밝힌다. 권한 검사는 자동 질문과 같은 코드로 한다.

**양도인 직접 답변:** "추가 자료 필요" 질문에 양도인이 글로 직접 답할 수 있다. 답은 "양도인 직접 답변(점주 진술)"으로 표시되고, 증빙이 없으므로 비교표 숫자는 바꾸지 않는다.

**답변 모으기 (양수인 AI)**
- 답변마다 대상 매물, 시각, 근거 자료, 신뢰 수준, 공개 권한 상태, 미확인 정보를 붙인다.
- 숫자가 서로 다르면 (예: 양도인 주장 월매출 5,000만 원 vs POS 자료 4,200만 원) 코드로 차이를 계산해 표시하고 추가 확인을 요청한다.
- 받은 답으로 비교표(F05)를 갱신한다.

완료 기준:
- 양수인 AI가 3개 매물의 양도인 AI에 동시에 질문할 수 있다.
- 각 양도인 AI는 자기 매물의 데이터룸만 검색하고, 근거와 함께 답한다.
- 권한이 없는 자료는 답변에 나오지 않는다. 승인 요청이 양도인 대시보드에 뜬다.
- 승인된 정보만 양수인에게 전달되고, 비교표가 갱신된다.
- 질문과 답변 기록이 새로고침 후에도 남는다.

## 6. 정보 접근 정책

| 등급 | 예시 | 볼 수 있는 사람 |
|---|---|---|
| L0 공개 | 업종, 대략적인 위치(동 단위), 희망 권리금 | 모든 사용자 |
| L1 NDA 후 공개 | 매출 요약, 양도인이 승인한 수익성 분석 | 본인확인 + NDA 체결한 양수인 |
| L2 승인 후 공개 | 정산 자료, 비용 내역, 임대차 상세 문서 | L1 조건 + 양도인이 개별 승인한 양수인 |
| L3 양도인 전용 | 공개하지 않기로 한 원자료, 개인정보 | 양도인 (와 허가된 운영·검증 담당자) |

원칙:
- 정보 공개는 양도인이 통제한다. 양도인은 항목별로 등급을 낮추거나 높일 수 있다.
- AI는 그 사람에게 허용된 데이터와 계산 결과만 전달한다.
- 질문을 반복해서 비공개 수치를 역산하는 것을 막는다.
- 한 양도인의 자료를 다른 매물이나 다른 구매자 분석에 재사용하지 않는다.
- 자료 열람과 권한 변경은 모두 기록한다.
- 개인정보와 제3자 정보(직원, 거래처 등)는 적법한 처리 근거를 확보하고 가린 뒤 다룬다.
- **권한 검사는 AI 프롬프트가 아니라 서버 코드에서 한다.** 파일 다운로드도 서버가 권한을 확인한 뒤 짧은 기간만 유효한 링크로 준다.
- 매물별 데이터는 서로 섞이지 않는다. L3 자료는 양수인 AI의 검색 대상에서 빠진다.
- 실제 전자서명·본인인증 서비스가 연결되지 않았으면 "서명 완료", "인증 완료"라고 표시하지 않는다. 테스트용 동의는 "테스트 동의(법적 효력 없음)"로 따로 표시한다.

## 7. AI 데이터와 검증

### 7.1 데이터 수집

초기에는 POS·배달앱 API 연동을 요구하지 않는다. 사용자가 가진 파일을 올리면 AI가 정리한다. 공식 API나 점주의 적법한 연결 권한을 확보할 수 있게 되면 자동 연동을 검토한다.

### 7.2 신뢰 수준

화면에 보이는 모든 재무·운영 숫자는 다음 중 하나의 상태를 가진다.

| 상태 | 뜻 |
|---|---|
| 점주 진술 | 점주가 직접 입력했고 증빙이 없는 값 |
| 자료 제출 | 올린 원본 문서와 연결된 값 |
| 교차 확인 | 서로 다른 자료끼리 일치하는지 확인한 값 |
| 외부 검증 | 공인 데이터나 전문가가 검토한 값 |
| AI 추정 | 밝힌 가정과 계산으로 도출한 값 |

자료를 제출했다는 것만으로 "매출 인증"이라고 표현하지 않는다.

### 7.3 AI 동작 원칙

- 출처 없는 숫자를 만들지 않는다.
- 실제 자료 값과 추정값을 구분해서 보여준다.
- 수익성 계산에는 비용, 기간, 점주 노동시간을 반영한다.
- 권리금을 하나의 "정답 가격"으로 말하지 않고 시나리오로 보여준다.
- 권한이 없으면 답하지 않거나 승인을 요청한다.
- 불확실성이 크면 추가 자료를 요청하거나 사람(전문가) 검토로 넘긴다.
- 쉬운 말로 설명하고, 전문 용어는 처음 나올 때 한 줄로 풀어준다.
- 양도인·양수인 어느 편도 들지 않는다. "사기", "허위" 같은 단정 대신 "자료 간 차이가 있어 확인이 필요해요"라고 쓴다.
- 법률·세무 판단은 결론 내리지 않고 전문가 확인을 권한다.

## 8. MVP 범위 (제품 기준)

### 8.1 MVP가 답할 질문

**양도인이 자료를 쉽게 등록하고 제한적으로 공개할 수 있으며, 양수인이 이를 바탕으로 여러 점포를 효율적으로 사전 검토할 수 있는가?**

### 8.2 포함

| 기능 | 범위 |
|---|---|
| 매물 등록 | 기본 정보 폼 + 빠진 항목만 AI가 질문 |
| 자료 수집 | PDF·엑셀·CSV·이미지 업로드 |
| 자료 구조화 | AI 추출·분류, 누락 정보 질문 |
| 매출 교차 검증 | 자료 간 비교, 신뢰도 등급, 확인 필요 항목 |
| 공개 관리 | 자료별 공개 등급, 양수인별 열람 승인 |
| NDA | 전자서명 연동, 체결 상태 확인 |
| 양수인 AI | 조건 저장, 승인된 자료 기반 질의응답 |
| 매물 비교 | 최대 3개 |
| 추가 자료 요청 | 양수인 질문을 양도인에게 전달 |
| 분석 리포트 | 수익성·신뢰 수준·위험 요인 요약 |
| 에이전트 간 통신 | 양수인 AI ↔ 양도인 AI 3개 질문·답변, 승인 요청, 기록 저장 |

초기에는 에이전트끼리 완전히 자율로 대화하지 않는다. AI가 질문과 답변 초안을 만들고, 필요한 부분은 사람이 승인한다.

### 8.3 제외

- 권리금 자동 협상·가격 합의
- 권리금·임대차 본계약 자동 체결
- 거래 대금 결제, 에스크로
- 공인중개 업무 대행
- 모든 배달앱·POS 실시간 연동
- 현장 실사 대체
- 수익 보장, 매출 진위 보증
- 인수인계 행정 절차 전체 자동화 (단계별 안내 체크리스트는 제공)

## 11. 이번 MVP에서 만드는 범위와 순서

### 11.1 데모 시나리오 (이게 실제로 동작해야 한다)

1. 양도인 A, B, C가 각각 매물을 등록하고 매출·비용 자료를 올린다.
2. AI가 자료를 분석하고, 양도인이 자료별 공개 등급을 정한다.
3. 양수인이 예산과 인수 조건을 입력하고 AI 실사 센터에서 시작 버튼을 누르면, 양수인 AI가 맞는 매물을 자동으로 고른다.
4. 양수인 AI가 고른 매물의 양도인 AI에 동시에 질문을 보내고, 대화가 매물별 대화창에 실시간으로 보인다.
5. 양도인 AI는 권한이 있는 자료만 검색해 답하고, 권한이 필요한 자료는 승인 요청으로 바꾼다.
6. 양도인이 승인하면 그 자료가 양수인에게 열린다.
7. 양수인 AI가 답을 모으고, 세 매물 비교표가 갱신되고, 최종 실사 리포트를 본다.

샘플 데이터가 필요하면 가상 음식점 3개를 만든다. 화면에 **"샘플 데이터"**라고 분명히 표시한다.

### 11.2 이미 있는 것 (재사용)

| 있는 것 | 상태 | 재사용 |
|---|---|---|
| 거래방 화면 (로드맵·체크리스트·채팅) | 가짜 데이터 | 매물별 양도인·양수인 직접 대화 공간으로 쓴다 |
| 거래방 만들기 폼 | 가짜 데이터 | 매물 등록 폼의 기본 정보 부분 |
| 자료 판독·교차 검증·리포트 (`lib/prepare.ts`, `lib/openai.ts`, `lib/verify.ts`, `ReportView`) | 코드 완성, OpenAI 키 문제로 AI 부분 미확인 | 데이터룸 AI 분석, 실사 리포트 |
| Supabase 테이블 (`deals`, `checklist_items`, `documents`, `messages`, `reports`) | 만들어짐, 서버 연결 코드 없음 | 확장해서 쓴다 (`deals` = 매물) |

| Step | 내용 | 완료 기준 |

| 2 | 매물·데이터룸: Supabase 저장, 매물 등록, 자료 업로드, AI 추출 결과 연결, 공개 등급 | 새로고침해도 매물·자료·공개 등급이 남는다 |

- 실제 전자서명: NDA는 "테스트 동의(법적 효력 없음)"로만 기록한다.
- 결제, 에스크로, 자동 계약 체결, 가격 합의
- 외부 유료 서비스, POS·배달앱 실시간 연동
- PDF 내보내기

### 11.5 AI 원칙 (이번 MVP)

- 코드가 하는 일: 금액·합계·차이·비율·수익성·회수기간 계산, 공개 권한 검사, 중복 질문 검사
- AI가 하는 일: 문서 분류·정보 추출, 질문 만들기, 검색 결과 요약, 답변 문장, 불일치·위험 설명, 양수인 조건 맞춤 해설
- AI 호출이 실패하거나 키가 없어도 매물 등록, 파일 저장, 권한 설정, 샘플 시연은 동작해야 한다. AI 문장이 없으면 코드가 만든 정해진 문구로 답하고, 화면에 "AI 요약 없음"이라고 표시한다.
- 같은 파일을 다시 분석하지 않는다 (분석 결과를 저장해 재사용).
- 실제로 통신하지 않으면서 통신하는 것처럼 보이게 만들지 않는다. 작동하지 않는 버튼을 만들지 않는다.

### 11.6 내 버전 (유지)

- 리포트 섹션: 핵심 위험 Top 3 (위험 내용, 근거 자료, 영향, 확인 방법)
- 추가 기능: 샘플 데이터로 시연하기 (가상 음식점 3개 + 양수인 1명)
