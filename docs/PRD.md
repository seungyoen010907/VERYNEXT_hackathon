# PRD: 점포 양도양수 계약 관리 에이전트

> 이 문서가 기준이다. AI(Claude Code / Codex)는 이 문서에 적힌 것만 만든다.
> 1~7번은 공통 뼈대라 그대로 두고, 8번 "내 버전"만 각자 채운다.

## 1. 한 줄 요약

양도인과 양수인이 챗으로 만나 대화를 나눌 때 AI가 절차 대로 진행해주고, 계약서를 만들고 AI와 전문가의 검토, 실제계약까지 진행해주는 웹 서비스. 점포 양도양수 계약 관리 에이전트

## 2. 문제

- 양도인이 제시한 매출·순수익이 사실인지 확인하기 어렵고, 부풀려진 정보를 믿고 권리금을 지불할 위험이 있다.
- 필요한 서류, 발급처, 확인 순서를 몰라 등기부·임대차 조건 같은 핵심 위험을 놓치기 쉽다.
- 상대가 나를 속이고 있거나 권리금 협상에서 내가 불리한 조건을 제시해도 정보를 잘 모르면 손해 보고 계약할 수 있다.
- 컨설턴트는 거래 성사로 수익을 얻어 검증 동기가 약하고,세무사·변호사를 각각 고용하기엔 비용이 크다.

## 3. 타깃 유저

- 1차: 점포를 인수해 창업하려는 예비 소상공인
창업 경험이 없거나 적어 양도양수 절차와 서류를 잘 모름
- 2차: 양도인 (점포를 팔려는 사장님)
매출을 인증받아 신뢰를 얻고, 제값에 빨리 팔고 싶음
- 3차: 제휴 전문가 (공인중개사·세무사·법무사) AI가 정리한 자료로 검토 시간을 줄이고 고객을 소개받음
-초기 집중 타깃: 업종: 카드·배달 매출 비중이 높은 음식점·카페를 인수하려는 사람
  → 매출 자료가 디지털로 남아 있어 검증하기 쉬움
    지역: 거래가 활발한 수도권 상권 한두 곳

## 5. 유저 플로우

> **오늘 세션 범위:** 아래는 완성된 서비스 기준 흐름이다. 오늘은 로그인·초대 없이 헤더의 역할 전환(양도인/양수인으로 보기)으로 시연하고, 2·4번(가입·초대)과 9~13번(조건 합의·계약서·계약 이후)은 만들지 않는다. 자세한 건 7번과 `docs/API.md` 1번.

### 양수인 (거래방을 만드는 쪽)

1. `/`에 들어와서 서비스 소개를 보고 "거래 시작하기"를 누른다.
2. `/login`에서 가입하거나 로그인한다.
3. `/deals/new`에서 점포 주소, 업종, 권리금, 보증금, 월세, 양도인이 말한 월매출·순수익을 입력하고 "거래방 만들기"를 누른다.
4. `/deals/[id]`로 이동한다. 계약 로드맵과 내 체크리스트가 보이고, "양도인 초대하기"를 눌러 초대 링크를 복사해 양도인에게 보낸다.
5. 양도인이 참여하면 알림이 온다. 거래방에서 메시지를 주고받으며 양도인의 자료 제출 상황을 체크리스트로 확인한다.
6. 자료가 모두 제출되면 "검증 중" 표시가 뜬다 (30초~1분).
7. `/deals/[id]/report`에서 검증 리포트를 확인한다. 월별 매출표, 주장 vs 실제 차이, '확인 필요' 항목, 신뢰도 등급, 협상 포인트를 본다.
8. 확인 필요 항목이 있으면 "양도인에게 소명 요청"을 누르거나, 문제없으면 "진행하기"를 누른다. 중단하려면 "거래 중단"을 누른다.
9. `/deals/[id]/terms`에서 양도인과 권리금, 넘겨받는 시설, 인수 날짜를 하나씩 합의한다. 양측이 모두 확인한 항목만 '합의 완료'로 바뀐다.
10. `/deals/[id]/contract`에서 합의 조건이 자동으로 채워진 권리금 계약서를 확인하고 "확인 완료"를 누른다. PDF로 받을 수 있다.
11. 거래방 로드맵을 따라 임대차계약, 잔금, 지위승계 신고, 사업자등록 항목을 하나씩 완료 체크한다.
12. 인수인계 체크리스트에서 양도인이 넘긴 항목을 하나씩 "받았어요"로 확인한다.
13. 모든 항목이 끝나면 "거래 종료" 화면이 뜨고, 전체 기록을 PDF로 받을 수 있다.

### 양도인 (초대받는 쪽)

1. 양수인이 보낸 초대 링크 `/invite/[code]`로 들어온다. 어떤 점포의 거래인지 확인한다.
2. 가입하거나 로그인하면 해당 거래방 `/deals/[id]`로 바로 들어간다.
3. 사업자번호를 입력해 사업자 인증을 하고, 자료 공개·AI 분석에 동의한다.
4. 내 체크리스트에서 제출할 자료 목록을 본다. 항목마다 "어디서 떼나요?"를 누르면 발급처와 방법이 나온다.
5. 항목별로 카드매출, 배달앱 정산, POS, 부가세 자료를 업로드한다. 올린 항목은 '제출 완료'로 바뀐다.
6. 에이전트가 추가 자료나 소명을 요청하면 알림이 오고, 거래방에서 자료를 더 올리거나 메시지로 설명한다.
7. 양수인과 조건을 합의하고, 권리금 계약서를 확인한다.
8. 인수인계 체크리스트에서 POS·배달앱 계정, 공과금 명의, 거래처 정보 등을 넘기고 항목별로 "넘겼어요"를 누른다.

### 공통

1. `/deals`에서 내가 참여한 거래방 목록과 각 거래의 진행 단계를 본다.
2. 목록에서 예전 거래방을 다시 열어 대화, 자료, 리포트, 계약서를 확인한다.

## 7. 이번에 안 만드는 것

- 회원가입·로그인·본인인증·사업자 인증: 헤더의 역할 전환(`x-role` 헤더)으로 대신한다 (`docs/API.md` 1번). 실제 사용자를 받기 전에 Supabase Auth로 바꾼다.
- 중개인·전문가 역할: 오늘은 `buyer`(양수인) / `seller`(양도인) 두 역할만 있다.
- 초대 링크: 거래방 하나를 미리 만들어 두거나 "샘플 자료로 시연하기"로 시연한다.
- PDF 내보내기 (검증 리포트, 계약서, 거래 기록): 오늘은 화면으로만 본다. PDF 패키지를 추가하지 않는다.
- 채팅 안 파일 보내기, 알림: 자료는 체크리스트 항목별 업로드로, 안내는 에이전트 메시지로 대신한다.
- 조건 합의·계약서·계약 이후 단계(P1): 시간이 남으면 한다.
- 매물 등록 / 검색: 이미 상대를 찾은 거래를 관리하는 서비스라 필요 없다.
- 외부 데이터 자동 연동 (여신금융협회, 홈택스, 배달앱, 은행, 등기소 등): 공개 API가 없다. 파일 업로드로 충분하다.
- 통화 / 화면 공유: 메시지와 파일 공유로 충분하다.
- 스트리밍 출력: 검증 중 로딩 표시로 충분하다.
- 모바일 앱: 반응형 웹으로 대체.
- 관리자 페이지 / 신고 기능, 요금제: 초기에는 수동 운영.

## 8. 내 버전

### 8-1. 누구를 위한 서비스인가

- 기본값: 점포를 인수해 창업하려는 예비 소상공인
- 내 선택: 수도권에서 카드·배달 매출 비중이 높은 음식점·카페를 처음 인수하려는 예비 창업자
  - 양도양수 절차와 필요 서류를 잘 모름
  - 양도인이 말한 매출·순수익을 검증할 방법이 없음
  - 전문가를 따로 고용하기엔 비용이 부담스러움

### 8-2. AI 성격 (프롬프트 톤)

- 기본값: 법률과 창업 지식을 갖춘 점포 양도양수 전문가
- 내 선택:
  - 쉬운 말로 설명하고, 전문 용어는 처음 나올 때 한 줄로 풀어준다.
  - 법·규제 문제(자격이 필요한 업무, 개인정보, 금융 규제)가 걸리면 미리 알려주고 안전한 대안을 제시한다.
  - 확실하지 않은 숫자나 사실은 지어내지 않고, 임의로 정한 값이면 그렇다고 밝힌다.
  - 바꾸자고 할 때는 항상 이유를 붙이고, 바로 쓸 수 있는 수정본을 같이 준다.
  - 양도인과 양수인 어느 쪽 편도 들지 않고, 제출된 자료와 확인된 사실을 근거로 말한다.
  - 법률·세무 판단이 필요한 내용은 직접 결론 내리지 않고 전문가 검토를 권한다.

### 8-3. 검증 리포트에 추가할 섹션 1개

- 예시: 핵심 위험 Top 3 / 권리금 회수 기간 / 비슷한 상권 매출 비교 / 양도인에게 물어볼 질문 5개
- 내 선택: 핵심 위험 Top 3
  - 위험 내용 (예: POS 6월 매출이 카드·배달 합계보다 41% 많음)
  - 근거 자료 (어떤 파일의 어떤 숫자인지)
  - 영향 (권리금·순수익 판단에 미치는 영향)
  - 확인 방법 (양도인에게 요청할 자료 또는 질문)

### 8-4. 추가 기능 1개

- 예시: 샘플 자료로 시연하기 / 리포트 PDF 다운로드 / 양도인에게 물어볼 질문 자동 생성 / 거래방 목록 검색
- 내 선택: 샘플 자료로 시연하기 버튼
- 완료 기준: 버튼을 누르면 가상 점포 '샘플분식' 거래방이 만들어지고 샘플 자료 4종이 업로드된 상태로 검증 리포트까지 바로 볼 수 있다.
